# Schema of the generated SOLAR Web data

Field-level reference for the two JSON files a generator consumes. Both are written by
[build-docs.mjs](build-docs.mjs) from [raw/](raw/README.md); the raw per-page format is
documented in [raw/README.md](raw/README.md#file-shape). Everything here is regenerated by
`npm run solar:docs`; do not edit the files.

Token references everywhere use the raw form `{Collection:figma/path}`, for example
`{Color:action/primary/bg/default}`. Translate with the separators in
[../solar/tokens/grammar.json](../solar/tokens/grammar.json): documentation name
`color.action.primary.bg.default`, CSS `--solar-color-action-primary-bg-default`. Resolved
values are in [../solar/tokens/css-contract.json](../solar/tokens/css-contract.json).
`{Layout:…}` is SOLAR Web's own local collection ([tokens/layout-grid.md](tokens/layout-grid.md));
`{Base Typograhy:…}` and `{Scale:…}` are legacy collections found only in documentation chrome.

## `catalog.json`

```jsonc
{
  "_note": "…",
  "generated": "2026-09-21", // date build-docs.mjs ran
  "count": 225, // length of components[]
  "components": [Record, …] // in raw/_pages.json manifest order, then Figma order within a page
}
```

### `Record`

| Field            | Type                                                 | Meaning                                                                                                                                                                                                                                                                                                                                                               |
| ---------------- | ---------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `name`           | string                                               | Figma component-set or component name, e.g. `Button`, `Icon Button`, `.Component Description`. Names starting with `.` are private helpers.                                                                                                                                                                                                                           |
| `kind`           | `"set"` \| `"component"`                             | `set`: a Figma component set with variants. `component`: a standalone component with a single tree.                                                                                                                                                                                                                                                                   |
| `section`        | string                                               | Path of the page doc relative to this folder, e.g. `components/buttons`, `patterns/forms`, `views/system`.                                                                                                                                                                                                                                                            |
| `slug`           | string                                               | Page slug. `section/slug.md` is the human page; `raw/section/slug.json` is the source.                                                                                                                                                                                                                                                                                |
| `pageId`         | string                                               | Figma page node id.                                                                                                                                                                                                                                                                                                                                                   |
| `nodeId`         | string                                               | Figma node id of the set or component. Use it to build a Figma deep link.                                                                                                                                                                                                                                                                                             |
| `description`    | string                                               | The component description written by the SOLAR team in Figma, verbatim. Contains variant lists, sizing notes, a11y rules and do/don't guidance. Empty string when none.                                                                                                                                                                                               |
| `variantCount`   | number                                               | Number of variants in the set (`1` for a `component`).                                                                                                                                                                                                                                                                                                                |
| `defaultVariant` | string                                               | Figma default variant name, `axis=value, axis=value`.                                                                                                                                                                                                                                                                                                                 |
| `axes`           | `{ [axis]: { options: string[], default: string } }` | Variant axes in Figma order. Axis names are as designed (`size`, `prio`, `state`, `danger`, …). `options` are the values that exist in the set, not the ones the description claims.                                                                                                                                                                                  |
| `props`          | `{ [prop]: { type, default } }`                      | Non-variant component properties. `type` is `BOOLEAN`, `TEXT`, `INSTANCE_SWAP` or `SLOT`. `default` is a boolean, a string, or for `INSTANCE_SWAP` a Figma component id. Figma's `#node:id` suffix is stripped from prop names.                                                                                                                                       |
| `variants`       | `Variant[]`                                          | Every variant of the set, default first. Each has the root digest (`size`, `fills`, `strokes`, `effect`, `textFills`, `iconFills`, `hidden`, `hiddenPaths`) and, for non-default variants, `overrides`: what the variant changes relative to the default variant's tree. `variantsTruncated` is true when a set has more than 151 variants and the rest were dropped. |
| `defaultSize`    | `[width, height]`                                    | Rendered px size of the default variant.                                                                                                                                                                                                                                                                                                                              |
| `layout`         | `Layout` \| absent                                   | Auto-layout of the default variant's root. Absent on the 14 components whose root has no auto-layout.                                                                                                                                                                                                                                                                 |
| `tokens`         | `{ [role]: string[] }`                               | Every variable bound anywhere in the default tree or the variant digest, grouped by role, each list sorted and deduplicated. Roles: `fills`, `strokes`, `text`, `icons`, `spacing`, `radius`, `borderWidth`, `size`, `typography`, `effects`, `textStyles`, `other`.                                                                                                  |
| `hardcoded`      | `Hardcoded[]`                                        | Literal values that should have been tokens. Empty on a clean component.                                                                                                                                                                                                                                                                                              |
| `slots`          | `Slot[]`                                             | Which prop drives which layer.                                                                                                                                                                                                                                                                                                                                        |
| `composes`       | string[]                                             | Names of components instantiated inside the tree (`Counter`, `Spinner`, `Icon/None`…). Their internals are on their own pages.                                                                                                                                                                                                                                        |
| `issues`         | string[]                                             | Automatic findings for this component, same text as in [issues.md](issues.md).                                                                                                                                                                                                                                                                                        |
| `docText`        | string[]                                             | Text content of the page's documentation card and frames, in reading order. Prose only; no styling.                                                                                                                                                                                                                                                                   |

### `Variant.overrides`

```jsonc
{
  "changed": {
    "/": {
      "fills": ["{Color:action/primary/bg/hover}"],
      "strokes": ["{Color:action/primary/border/hover}"],
    },
    "/Label": { "fills": ["{Color:action/primary/text/hover}"] },
    "/Counter": { "variant": { "type": "inverted", "state": "hover" } },
  },
  "added": [
    // layers that exist only in this variant, with their own properties, their parent's path and
    // their place among its children in this variant
    {
      "path": "/Spinner",
      "parent": "/",
      "index": 1,
      "layer": { "name": "Spinner", "type": "INSTANCE" },
    },
  ],
  "removed": ["/Icon/None#2"], // layers of the default variant that this variant lacks
}
```

Keys of `changed` are layer paths in the default variant's tree (`/` is the root; `#2`
marks the second sibling of the same name). Values hold only the fields that differ:
`hidden`, `text`, `textStyle`, `main`, `variant`, `size`, `position`, `layout`, `sizing`, `fills`,
`strokes`, `strokeWeight`, `strokeWeights`, `radius`, `effectStyle`, `opacity`, `vars`. For `vars` and
`layout` only the changed sub-keys appear; `null` means the default had it and the variant
does not. This is the input for generating per-variant styles: start from the default tree,
apply `changed`, add and remove the listed layers.

An added layer carries its properties in the same shape as a tree layer, without `children`
(each child is an added path of its own), and its parent's path, because a path cannot be split
to find it: layer names contain `/` themselves. Raw data fetched before 2026-09-23 has the path
alone, which codegen refuses. `index` is where the layer sits among its parent's children in the
variant (Card's loading title placeholder, first, above the content); data fetched before
2026-09-25 lacks it, and codegen then puts the layer after its siblings, which an overlay's
`places` corrects.

The digest's `hidden` names every layer the variant hides, at any depth and inside the instances
the tree does not descend into; `hiddenPaths` gives the same layers by path, in the tree's
addressing (`/Content/Dropdown/Label`), so a composed child's hidden layer is told from one of the
same name elsewhere (Device Card's Dropdown label and Tag words, both `Label`). Both are recorded
on the default variant, and on another only where they differ from the default's. Data fetched
before 2026-09-25 has `hidden` alone, and codegen then reads a child's hidden layers by name, which
an overlay's `hides` corrects.

A stroke whose sides differ in weight has `strokeWeight: "mixed"` and, beside it, `strokeWeights`:
the four weights, top, right, bottom and left (Button Group's full-width bar draws a divider along
its top only). Each side's variable binding is under `vars`
(`strokeTopWeight`…). Data fetched before 2026-09-23 has `mixed` alone; codegen then draws a side
where it is bound and reports the layer as `unrecorded` until a sync records the weights.

A layer its parent's auto layout does not place, a child of a frame with no auto layout or one
positioned absolutely inside one, has `position`: its top-left, `[x, y]` in pixels to the
hundredth, relative to its parent's, from the two bounding boxes (StatusIndicator's `!` inside its
triangle, a Toggle's knob). A layer auto layout places has none: its place follows from the
layout. Data fetched before 2026-09-24 has no positions.

An `INSTANCE` of an icon (`main` starting `Icon/`) records `iconFills`: the distinct fills of the
vectors inside it, which the tree does not descend into. It is diffed like any other property,
so a variant whose icon changes colour says so under `changed`. An icon with no painted vector
(`Icon/Empty`, a placeholder) has none. The variant digest's `iconFills` is different: it also
lists the icons inside composed children (Button Group's Buttons), which belong to those
children, so it says which colours a variant shows, not which layer shows them.

A `VECTOR`, `BOOLEAN_OPERATION`, `LINE`, `STAR` or `REGULAR_POLYGON` layer records its shape, the
only place a drawn glyph's outline exists (Checkbox's tick and dash, StatusIndicator's marks,
Sparkline's sample line): `geometry`, Figma's `fillGeometry`, and `strokeGeometry` when the layer
has strokes, each a list of `{path, windingRule}` with SVG path data in the layer's own coordinates
(its `size` is the box). A rectangle or an ellipse records none, since its size and radius
describe it. Both are diffed per variant like any other property. The fetcher asks for them with
`geometry=paths`; data fetched before 2026-09-23 has neither.

A colour bound to a variable carries no opacity suffix. For a bound paint REST reports the
variable's own alpha as the paint's opacity, and the token already holds it: in all 1742 bound
paints with an opacity, measured 2026-09-23, it equalled the token's alpha. Only an unbound
colour's `a=` is its own.

### `Layout`

```jsonc
{
  "dir": "HORIZONTAL", // HORIZONTAL | VERTICAL
  "gap": 8, // px between children
  "pad": [0, 12, 0, 12], // top, right, bottom, left in px
  "align": "CENTER/CENTER", // primary axis / counter axis
  "sizing": "HUG/FIXED", // horizontal / vertical: HUG | FIXED | FILL
}
```

`gap` and `pad` are the rendered numbers. Whether they are bound to tokens is visible in
`tokens.spacing`; if a value appears in `hardcoded` with `prop` `gap` or `padding*`, it is not.

### `Hardcoded`

```jsonc
{ "layer": "Label", "prop": "gap", "value": "4px" }
```

`layer` is the layer name (or a variant name when the root itself is at fault), `prop` the
CSS-like property (`gap`, `paddingRight`, `fill`, `cornerRadius`, `strokeWeight`…), `value`
the literal (`8px`, `#1a1a1a`).

### `Slot`

```jsonc
{ "layer": "Icon/None", "controls": "visible", "prop": "hasIconLeading" }
```

| `controls`      | Meaning                                                                 |
| --------------- | ----------------------------------------------------------------------- |
| `visible`       | A `BOOLEAN` prop shows or hides the layer                               |
| `mainComponent` | An `INSTANCE_SWAP` prop replaces the layer's component (icons, avatars) |
| `characters`    | A `TEXT` prop sets the layer's text                                     |
| `slotContentId` | A `SLOT` prop injects arbitrary children into the layer                 |

The same layer may appear several times, once per prop that touches it.

## `token-usage.json`

```jsonc
{
  "_note": "…",
  "generated": "2026-09-21",
  "tokens": {
    "color.action.primary.bg.default": ["Button", "Icon Button", …], // documentation dot-name → component names
    "0,875rem": [".Component Description"] // legacy collections keep their raw name
  }
}
```

Keys are documentation dot-names (`color.…`, `inset.…`, `radius.…`, `shadow.…`, `layout.…`),
values are `catalog.json` `name`s sorted alphabetically. A Foundations token that never
appears here is not consumed by any SOLAR Web component. Hard-coded values are not tokens
and are only in `catalog.json`.

## What a generator can and cannot get from these files

Can:

- The complete public surface of a component: variant axes with real options and defaults,
  boolean/text/swap/slot props, composition.
- Every token the component binds, by role, and the default variant's layout metrics.
- Which layer each prop drives, so slots and conditional rendering can be derived.
- Per-variant root fill, stroke, effect, and inner text and icon colors, in the page's
  Markdown variant matrix and in `raw/<section>/<slug>.json` under `variants[]`.
- Designer intent and a11y requirements as prose (`description`, `docText`).

Cannot (see the limits section in [README.md](README.md#limits-of-the-extracted-data)):

- Motion, prototype interactions, or behaviour beyond what the description says in words.
- Layers deeper than six levels (three on components with more than 300 nodes), in any
  variant, and the internals of nested component instances, which live on their own pages.
- Resolved values. Resolve through `css-contract.json`; never through the Web file.
